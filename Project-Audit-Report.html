Project Audit Report

考研学习工具优化审查报告

这是一份面向当前项目的结构化优化文档，重点不是继续堆功能，而是先把现有功能收成一个统一、稳定、可维护的产品外壳。

可编辑模式已开启：下方正文区域支持直接修改

一、项目当前总体判断

当前项目已经具备首页、任务、错题、知识点、搜索、统计、数据管理等核心页面雏形，也已经开始接入 Supabase。 但从代码结构、页面一致性和长期维护角度看，项目已经出现明显的“继续堆功能会越来越乱”的趋势。

当前最核心的问题不是“功能太少”，而是数据源没有统一、页面骨架没有统一、视觉 token 没有收口、page client 容器过重。

1.1 总览评级

维度 当前状态 评级 说明
产品方向 明确 好 个人考研学习工具定位清晰，没有跑偏。
MVP 范围 基本完整 好 任务、记录、搜索、统计、导入导出均已覆盖。
页面完成度 中等 中 页面可访问，但结构和一致性不足。
视觉统一性 偏弱 差 首页、模块页、统计页风格割裂。
数据层稳定性 偏弱 差 mock、本地缓存、Supabase 三套并存。
工程可维护性 开始恶化 差 重复逻辑明显，page client 文件过重。
正式可上线性 不足 差 鉴权、错误处理、附件链路还不稳。

二、P0 阻塞问题

2.1 Supabase 接入方式需要立即收紧

问题 当前情况 风险 优化建议
API 鉴权缺失 路由层主要依赖环境变量存在与否。 正式部署后存在越权风险。 接入 Supabase Auth + user_id + RLS。
service role 直接承担业务访问 API 直接透传高权限访问数据库。 业务边界过宽。 改为最小权限服务端访问策略。
缺少服务端输入校验 POST/PATCH 数据接近裸写。 容易写入脏数据。 给任务、学习记录、上传接口增加 schema 校验。

2.2 数据源混乱必须先统一

问题 当前情况 风险 优化建议
mock、本地缓存、Supabase 共存 每页都可能读到不同来源。 搜索、统计、导出结果失真。 明确单一事实来源。
Supabase 空库不接管页面 远端为空时页面继续显示 mock。 fresh project 仍展示假数据。 远端为空也应视为真实状态。
页面各自处理同步 每个页面都自己拉取和写回。 重复逻辑越来越多。 抽共享数据同步 hook。

2.3 文案乱码与 token 漂移

问题 当前情况 影响 优化建议
中文乱码 导航、按钮、标题、说明文案存在乱码。 直接影响可用性。 统一使用 UTF-8 重写高频文案。
未定义 class 被频繁使用 bg-moss-*、shadow-float、safe-bottom 渲染不可控。 补齐设计 token 或替换成现有定义。
视觉系统未闭环 只有少量全局样式，其余大量局部硬写。 难以统一改版。 建立真正的颜色、圆角、阴影、间距体系。

三、页面结构与信息架构问题

3.1 首页问题

问题 当前情况 建议
首页结构未完全落地 DatePanel、QuickAccessCard 未完整接入首页主流程。 回到 `日期 / 倒计时 / 今日任务 / 随机知识点 / 快速入口` 五区结构。
首页职责漂移 路由文件中内联统计和进度内容。 首页仅保留摘要，统计页负责正式复盘。
首页与统计页口径脱节 首页和统计页都在展示趋势，但口径不同。 统一统计来源。

3.2 任务页问题

问题 当前情况 建议
手机端不是列表优先 先概览、再筛选、再列表。 手机端应改成任务列表优先。
详情不适合手机 详情直接堆在列表后面。 改成全屏详情或抽屉详情。
任务进度展示分散 步骤、状态、进度分别散落在不同组件。 抽统一任务进度组件。

3.3 结构类页面问题汇总

页面 当前问题 优化方向
错题页 / 知识点页 结构高度平行，重复实现多。 共享 `List + Detail` 骨架，只保留字段差异。
搜索页 手机端筛选过重，结果与详情联动不够稳定。 搜索优先，筛选抽屉化，明确选中态规则。
统计页 与首页摘要职责重叠。 首页只保留轻摘要，统计页负责正式复盘。
数据管理页 导入、导出、概览、预览都堆在一个容器里。 强化“导出模式 / 导入模式”切分。

四、响应式与三端体验问题

终端 当前问题 建议目标
手机端 详情和筛选偏重，底部导航不完整。 单列、列表优先、全屏详情、完整底部导航。
平板端 双栏有雏形，但左右区规则不统一。 固定左列表右详情，筛选可折叠。
电脑端 顶栏 + 页头 + 侧栏层级偏重，页面气质不统一。 统一为 `概览/筛选 + 列表 + 详情` 三段式。

五、代码结构与复用问题

5.1 当前明显重复的逻辑

重复项 分布位置 建议
usePersistentCollection + remote fetch 任务、错题、知识点、搜索、统计、数据管理 抽共享同步 hook。
reviveTasks 多处重复定义 抽到任务模块工具层。
列表 + 详情布局模式 任务、错题、知识点、搜索 抽共享布局骨架。
筛选字段 UI 多个 filter panel 抽统一 `FilterField` 级别组件。

5.2 全局组件层不成熟

现状 问题 建议
全局组件主要只有 SectionCard、ProgressBar、ProgressRing 不足以支撑完整设计系统。 新增 Button、Badge、Modal、EmptyState、FilterField 等。
部分组件定义了但未真正使用 增加理解成本。 清理废弃组件，减少噪音。

六、接下来如何继续优化

6.1 分阶段优化路线

阶段 目标 核心动作 优先级
Phase 1 止血 修乱码、收 token、统一数据源、建立错误反馈、补最小校验 P0
Phase 2 收敛页面结构 重构首页信息架构，统一列表-详情骨架，收口导航层级 P1
Phase 3 重构数据层与组件层 抽共享 hook、拆 page-client、收敛类型与服务边界 P1
Phase 4 补完闭环 打通上传、归档、统计口径和导入导出边界 P1-P2
Phase 5 品质增强 无障碍、完整状态四态、测试、PWA 细节 P2-P3

6.2 推荐执行顺序

顺序 任务
1修复乱码文案
2修复 Tailwind token 漂移与未定义 class
3统一数据源策略
4建立错误反馈与最小表单校验
5重构首页信息架构
6统一任务、错题、知识点、搜索四页的列表-详情骨架
7抽共享 hook 和共享 UI 组件
8打通上传和归档闭环
9最后补无障碍、测试、PWA 细节

七、一句话结论

当前项目最需要的不是“继续长功能”，而是先把已有功能收成一个统一、稳定、可维护的产品外壳。

最优先要做好的五件事

  • 文案编码
  • 设计 token
  • 数据源统一
  • 页面骨架统一
  • 共享 hook / 共享组件收口
